기준 커밋 HEAD = dc6e45e · "일단 저장" · 2026-06-15 · 핵심 모듈 peetsfea_runner/single_simulation_remote.py

GOAL.md가 정의한 Single Remote PyAEDT API Runner 경로. 레거시 Slurm 번들/host /tmp/배치 AEDT 경로는 폐기되었으며, 아래 단일 시뮬레이션 경로만 작동 대상입니다.

1. 한눈에 보는 구성

로컬 컨트롤러가 단일 Slurm 잡을 띄우고 → 그 잡이 단일 Enroot 컨테이너를 띄우고 → 컨테이너 안의 단일 Python API 서버가 PyAEDT 시뮬레이션 하나를 처리합니다. 스토리지는 RAM(/dev/shm) 스크래치 + sshfs 역방향 워크스페이스 조합입니다.

3. 스토리지 정책 — tmp · sshfs · /dev/shm

RAM (/dev/shm) sshfs 워크스페이스 job-local fallback 레거시(미사용)

/dev/shm — RAM 백엔드 스크래치 활성

경로용도위치
/dev/shm/peetsfea-single-api-$SLURM_JOB_ID/enroot/{runtime,cache,data,tmp} Enroot 런타임/캐시/데이터/임시 — host /tmp 대신 RAM single_simulation_remote.py:517–526
/dev/shm/peetsfea-single-api-$SESSION/{tmp,ansys_work,uv_cache,pip_cache} 컨테이너 내부 TMP/TEMP/TMPDIR, ANSYS_WORK_DIR, uv/pip 캐시 single_simulation_remote.py:573–588

잡/컨테이너 종료 시 rm -rf로 정리됩니다 (trap cleanup). mkdir -p 실패 시에만 fallback으로 강등.

sshfs — 로컬 워크스페이스 역방향 마운트 활성

  • 로컬 측 루트: build/single_simulation_sshfs/<session>/output (로컬 PC에서 준비) — :60–63, :701
  • 컨테이너가 컨트롤 호스트로 되돌려 마운트: sshfs … $PEETS_WORKSPACE_REMOTE → /workspace — :596
  • 마운트 옵션: reconnect, idmap=user, uid=0,gid=0, StrictHostKeyChecking=no, IdentityFile=/etc/peetsfea_ssh/id_control
  • 출력 루트: PEETS_OUTPUT_ROOT=/workspace/output → CSV/아티팩트가 sshfs로 로컬에 직접 기록 — :598–599
  • 정리: fusermount3 -u (실패 시 fusermount/umount fallback) — :563

원격 계정 파일시스템은 용량 제약이 있어 durable 저장소로 쓰지 않음 — 결과는 로컬 DuckDB + sshfs 워크스페이스가 진실.

tmp — job-local fallback만 사용 제한

  • host /tmp를 runner 런타임 루트로 사용하지 않음 (GOAL.md 정책).
  • /dev/shm 확보 실패 시에만 컨테이너 내 /work/container_tmp, /work/ansys_work로 강등 — :580–583 (이 /work는 sshfs가 아닌 job-local $JOB_DIR 바인드).
  • 로컬 측: web_status.py:509의 아티팩트 tempfile.NamedTemporaryFile (패키징 한정).

이미지 빌드 보조 경로 빌드 전용

peetsfea_runner/enroot_image_bootstrap.sh: 이미지에 openssh-client sshfs fuse3 설치·검증, 빌드 임시 $HOME/runtime/enroot/build_tmp, 컨테이너 내 /tmp/miniconda.sh 등. 런타임 경로 아님.

레거시 — 작동 환경 아님 폐기

  • runtime_policy.py:7 /tmp/$USER/peetsfea-runner, :14 JOB_TMPFS_SIZE_GB
  • systemd_worker.py:143 /tmp disk_usage

GOAL.md "Temporary Storage Policy"에서 host /tmp runner 루트, host /tmp 기반 Enroot 경로를 명시적으로 금지.

4. 실행 흐름 (end-to-end)

  1. stage 준비 — build/single_simulation_remote/<session>/에 API 서버 스크립트, sbatch 스크립트, peetsfea_source.tgz 생성. 로컬 sshfs output 디렉터리 준비.
  2. 업로드 + 제출 — scp로 stage 전송 → ssh … sbatch --parsable로 잡 제출, job id 파싱.
  3. 잡 기동 — /dev/shm에 Enroot RAM 루트 생성, peetsfea_source.tgz 전개, container_run.sh/container_env.sh 생성, 컨트롤 SSH 키를 /etc/peetsfea_ssh/id_control로 마운트.
  4. 컨테이너 시작 — enroot start --root --rw로 AnsysEM·라이선스·$JOB_DIR:/work·/dev/fuse 마운트. 컨테이너가 sshfs로 /workspace 마운트.
  5. API 헬스 — 컨테이너 내 :18888/health를 폴링(최대 300s)하여 준비 확인. peetsfea 0.3.1 import 가능 + idle 확인.
  6. 역방향 터널 — 컨테이너 → 컨트롤 호스트로 ssh -R 127.0.0.1:LOCAL:127.0.0.1:18888 수립. 로컬 클라이언트는 http://127.0.0.1:LOCAL로 호출.
  7. 시뮬레이션 — POST /simulate(TOML 1건) → run_ssw_random_sample_reports_from_toml_text(...) 1회 solve. single-flight: busy 중 요청은 409.
  8. 결과 회수 — 결과 envelope 반환 + CSV/아티팩트는 sshfs로 로컬 워크스페이스에 기록 → 로컬 DuckDB에 영속화.
  9. 정리 — POST /shutdown 또는 scancel. trap이 터널·컨테이너·/dev/shm RAM 루트·sshfs 마운트를 정리.

5. HTTP API 계약 (컨테이너 내부 서버)

엔드포인트동작
GET /healthstatus/busy, account/host, peetsfea 버전 및 0.3.1 일치 여부 반환
POST /simulateTOML 1건 처리. busy면 409, 잘못된 요청 400, 성공 200 / 실패 500 + 구조화 에러. 단일 flight 락.
POST /shutdown서버 graceful 종료 트리거

서버는 build_remote_single_simulation_server_script()가 생성하는 표준 라이브러리 ThreadingHTTPServer 기반. 준비되면 /work/api.ready에 헬스 스냅샷 기록.
