  • 슬롯 = process-per-slot: edtmgr warm-pool 대여 대신, 컨테이너마다 단일슬롯 워커 11개를 별도 OS 프로세스로 spawn(pyaedt Desktop은 프로세스 전역 싱글톤이라 1프로세스=1AEDT). baseline 전역 샘플링으로 자기공급(Intake 없이도 상시 시뮬).
  • 단일 로컬 DB 토폴로지: 슈퍼컴엔 DB 없음. 컨테이너가 결과를 gate 경유 역터널(:7876 JSON, :7877 대용량)로 로컬 데몬에 push. 컨트롤 플레인은 로컬 systemd --user.
  • GPU 자동 가속: gpu* 파티션에 --gres=gpu:2 + 워커별 CUDA_VISIBLE_DEVICES 핀닝. 실측 성공의 41%가 GPU(RTX3090) 사용.
  • 파티션 = cpu2 + gpu1만: gpu2/3/4/6은 타 유저 점유로 예상시작 13~36h(영구 PENDING) → 여유 있는 두 파티션으로 제한해 8~9잡 즉시 가동.
  • 잡 수명 15h(10h×1.5), seed 대역 잡별 분리(중복탐색 제거), keep-best(성공 보호).

3. edtmgr 동작 & 타이밍

왜 필요한가

ansysedt는 켜고 끄는 비용이 매우 크고, 끄면 EDT 라이선스를 놓친다. edtmgr는 별도 시뮬이 아닌 관리용 pyaedt 세션을 상시 물고 있어 ansysedt를 warm으로 유지하고 라이선스 점유를 이어 간다.

  • acquire — 관리 점유만 잠깐 놓음(ansysedt는 살림) → {pid, grpc_port} 반환
  • 시뮬 pyaedt가 같은 ansysedt grpc에 접속·실행
  • done/release — 관리세션 재부착 → 다음 fixed toml 대기

시간 임계값 0.3.6 실값

시점동작
~90분소프트 목표(정보용). 실측 solve 중앙 55·p90 86분.
140분시뮬 자체 hard abort → 마지막 완료 패스 리포트
150분백스톱 — ansysedt SIGKILL → 재기동

초기 98분 백스톱에선 슬로우테일이 BackstopTimeout으로 죽어(실패의 30%) 150분으로 상향. 0.3.7: mesh 90k→40k·MaxPass 18→11로 solve <30분 목표 → 타임아웃 소멸·임계값 하향 가능.
