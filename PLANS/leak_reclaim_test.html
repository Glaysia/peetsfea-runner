2. 부트스트랩 스크립트 (수동 · wipe-safe)

게이트 데이터를 다 지워도 이걸로 재구축. 같은 게이트 머신이라 harry261의 동작하는 venv를 복제 + 경로 수정이 가장 빠르고 확실(동일 환경 보장). enroot 이미지는 이미 있음.

SRC=/home1/harry261/edt-deploy        # 동작 검증된 원본
DST=/home1/hmlee31/edt-deploy
G=gate1-hmlee31

# 1) edt-deploy 복제 (venv + 스크립트). 같은 게이트 fs라 게이트 안에서 cp -a.
ssh $G "rm -rf $DST && cp -a $SRC $DST 2>/dev/null || rsync -a $SRC/ $DST/"
ssh $G "mkdir -p $DST/clogs ~/runtime/enroot"

# 2) venv 경로 재지정 (harry261 → hmlee31). uv venv는 base python이 공유경로라 대부분 relocatable;
#    pyvenv.cfg / bin shebang / activate의 절대경로만 치환. 우리는 \$VENVPY -m 로 호출(심링크 resolve면 OK).
ssh $G "grep -rIl '/home1/harry261/edt-deploy' $DST 2>/dev/null | xargs -r sed -i 's#/home1/harry261/edt-deploy#/home1/hmlee31/edt-deploy#g'"
ssh $G "$DST/venv/bin/python -c 'import peetsfea_runner, peetsfea, pyaedt, cadquery; import peetsfea_runner.edt_entrypoint; print(\"venv OK\", peetsfea.__version__)'"

# 3) slot_service(orchestrator) 최신본 배포 (로컬 레포 → 게이트)
scp deploy/orchestrator.sh $G:$DST/slot_service.sh

# 4) (대안) 복제가 깨지면 깨끗한 재설치:
#    ssh $G 'uv venv --python 3.12 ~/edt-deploy/venv'
#    로컬에서 harry261 venv의 정확한 패키지 목록 확보:  ssh gate1-harry261 '~/edt-deploy/venv/bin/python -m pip freeze' (또는 uv pip freeze)
#    → 그 목록 + peetsfea-0.3.8.1 wheel + peetsfea_runner wheel 을 scp 후 uv pip install --python ~/edt-deploy/venv

실행 시 (1)~(3)로 안 되면 (4) 깨끗 재설치로 폴백. 핵심 검증은 venv OK 줄(peetsfea_runner·peetsfea·pyaedt·cadquery import).
