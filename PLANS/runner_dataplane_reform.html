Runner ⇄ Learning 데이터플레인 계약 v2.0

바이트 단위 확정 계약. 양측이 이 문서만 보고 독립 구현해도 일치한다. 합의로 미루는 항목 없음 · 2026-06-25

이 문서의 지위. 이건 위시리스트가 아니라 규범적(normative) 계약이다. 아래 스키마·dtype·엔드포인트·인코딩·커서 규칙은 그대로 구현 대상이며, "추후 협의" 항목은 없다. MUST = 필수, SHOULD = 권장. 변경은 §11 절차로만.

0비협상 원칙 (Hard constraints)

  • MUST 분석 핫 경로에 CSV/JSON 텍스트로 직렬화된 측정값이 절대 존재하지 않는다. 모든 수치는 타입 있는 컬럼형 바이너리(Arrow)로만 흐른다. csv_text_by_report_json 같은 필드는 v2 어떤 응답에도 없다.
  • MUST 모든 fetch는 증분이다. 클라이언트는 단조 정수 커서 seq 하나로 "이미 본 것 이후"만 받는다. 풀 재전송 경로는 존재하지 않는다(since=0은 최초 1회 부트스트랩일 뿐 동일 데이터 재수신 불가).
  • MUST 컬럼 프로젝션. 클라이언트가 필요한 컬럼만 요청한다. 기본 응답에 주파수 스윕은 포함되지 않는다(별도 엔드포인트).
  • MUST 측정→컬럼 변환(파싱)은 쓰기(ingestion) 시점 1회. 읽는 쪽은 절대 파싱하지 않는다.
  • MUST append-only·immutable. terminal 상태가 된 row는 이후 변경 없음. seq는 재사용·역행 없음.

1전송 포맷 (Wire) BOTH

  • MUST 바디 = Apache Arrow IPC stream format (RecordBatch 연속). Parquet 파일 직빵 서빙도 허용하나 기본은 Arrow IPC stream.
  • MUST 압축 = Arrow IPC body buffer compression = ZSTD (메시지 자체에 코덱 기록 → 자기서술적, HTTP Content-Encoding 불필요).
    pa.ipc.IpcWriteOptions(compression="zstd") 로 기록, 읽기는 pa.ipc.open_stream 가 자동 해제.
  • MUST Content-Type: application/vnd.apache.arrow.stream
  • MUST 숫자 dtype 고정: 실수=float64(double), 정수/커서=int64, 시각=timestamp[us, tz=UTC], 문자열=utf8(저카디널리티는 dictionary<utf8> 허용). null 허용 컬럼은 Arrow validity bitmap 사용(빈 문자열/0으로 위장 금지).
  • MUST 행 순서 = seq 오름차순.

5커서 · 증분 의미론 (엣지케이스까지) BOTH

  • MUST seq는 전역 단조증가, row 확정 시 할당, 갭 허용, 재사용/감소 없음.
  • MUST 페이징: 응답 limit행 가득 차면 X-Has-More:true. 클라는 since = X-Next-Since로 반복. row의 seq가 아니라 헤더 X-Next-Since로 전진(필터로 0행 페이지여도 커서 전진 보장 → state 필터 시 무한 재스캔 방지).
  • MUST idempotent: 같은 since 재요청은 같은 결과. 신규 없으면 0행 + X-Has-More:false, 수백 바이트, <200ms.
  • MUST immutability: seq가 응답에 나온 순간 그 row는 불변. (집계/재계산으로 과거 row 값이 바뀌면 계약 위반.)
  • SHOULD 서버 타임아웃/대용량 시 limit로 조절. 클라는 X-Has-More 따라 자연히 페이징.

6의미 매핑 — 컬럼 → surrogate 타깃 BOTH (합의된 의미)

양측이 "이 컬럼이 무엇인지" 동일하게 이해하도록 고정. featurization(아래)은 learning이 수행.

surrogate 타깃출처계산
R_tx_mOhm / R_rx_mOhmop_re_z11 / op_re_z22×1000 (Ω→mΩ)
M_nHop_im_z12|op_im_z12| / (2π·f_op) ×1e9
conv_deltamax_mag_delta_s그대로 (≤0/null→mask)
L_tx_uH / L_rx_uHsweeps.im_z11 / im_z22im_z / (2π·f) at 최저 freq ×1e6
C_tx2_pF / C_rx2_pFsweeps.im_z11 / im_z22im_z의 +→− 영점(자기공진 f_SRF) → 1/(L·(2π f_SRF)²) ×1e12

즉 M·R·conv·loss는 results 스칼라만으로, L·C2는 sweeps만 있으면 추출된다. 스칼라 fetch가 항상 핫, 스윕은 신규 설계에만.

10버전·변경관리 §11 BOTH

  • schema_version (health). v2.x = additive only(신규 nullable 컬럼). 기존 컬럼 dtype/의미 in-place 변경 MUST NOT.
  • breaking 변경은 /api/v3 신설 + 병행 기간. 무단 변경 금지.
  • 컬럼 추가/제거는 이 문서 개정 + 양측 ack 후.

이 계약은 코드가 아니다. 그러나 위 §2/§3 스키마와 §4 시그니처는 구현이 정확히 따라야 하는 사양이며, runner와 learning은 이 문서만으로 독립 구현해도 P1 동일성 게이트를 통과해야 한다. 통과하지 못하면 그건 구현 버그이지 계약 모호성이 아니다.
