Postgres 이관 + 대시보드 보강 미구현 · dev 개발 → main 배포

작성 2026-06-18 · 백엔드 2차(OLTP를 DuckDB→Postgres) + 대시보드 2건(솔브중 0 / 라이선스 표기) · dev에서 전부 개발·검증 후 main FF
한 줄. 운영 store를 임베디드 DuckDB → client-server Postgres(MVCC)로 옮겨 메모리·동시성·spill 문제를 근본 제거하고, DuckDB는 parquet export/분석 전용(콜드)으로 남긴다. 같은 작업에 대시보드 2건(컨테이너 "솔브중" 정확화, electronics_desktop 라이선스 표기)을 함께 처리. 인테이크 어댑티브 미가동이라 대시보드 자유 변경 가능. dev에서 개발·검증 완료 후 main 배포.

1. 제약 / 전제 (먼저 확인됨)

  • Postgres 미설치 + sudo 불가 → 시스템 패키지 불가. 유저공간 Postgres(conda)로 설치·구동(initdb/pg_ctl, 비root). ~/miniconda3 있음.
  • psycopg 드라이버 없음 → venv에 uv pip install psycopg[binary].
  • parquet export: Postgres는 네이티브 parquet 불가 → DuckDB가 Postgres를 ATTACH해 COPY (SELECT … FROM pg.…) TO parquet로 서빙(OLTP=PG, OLAP/export=DuckDB-over-PG). DuckDB는 store에서 은퇴, export 엔진으로만 잔존.
  • 응급픽스 현황: 지금은 DuckDB memory_limit=24GB로 spill/fd-fatal을 임시 봉합한 상태(안정). 이 이관이 그 근본해결.
  • 분리 1차 완료: 폴러+라이선스제어기는 이미 keeper로 격리됨(텔레메트리 무영향). web=대시보드/ingest/bulk.

2. 목표 아키텍처

 슈퍼컴 워커 ──역터널──▶ ingest(:7876, web)  ─writer─▶ ┌──────────────┐
                          dashboard(:8080, web) ─reader─▶│  Postgres     │  (OLTP·MVCC)
                          intake/lease (priority_*)─────▶│  (유저공간)   │  동시 read+write
                                                          └──────▲───────┘
 /results.parquet  ── DuckDB(ATTACH postgres) ─COPY→parquet ─────┘  (OLAP/export 전용)
 resource_snapshots: keeper 전용(현행 소형 DB 유지 or PG 같이) — 폴러 격리 유지

핵심: store(single_simulation_store)를 백엔드 추상화로 감싸 DuckDB/Postgres 드라이버를 토글(EDT_STORE_BACKEND). 호출부(ingest/dashboard/intake/lease) 변경 최소화 + 즉시 롤백 가능.

3. Postgres 셋업 (유저공간, 비root)

  1. conda create -n pg -c conda-forge postgresql (또는 기존 env에 설치).
  2. initdb -D ~/edt-deploy/pgdata → ~/edt-deploy/pgdata/postgresql.conf: port=5433(충돌회피), shared_buffers·work_mem 적정, listen_addresses='127.0.0.1'.
  3. systemd --user 유닛 peetsfea-pg.service: pg_ctl -D … start (web/keeper보다 먼저 기동되게 의존). 자동회수·재시작.
  4. DB·롤: createdb peetsfea, 롤 peets, 로컬 trust 인증(루프백 전용).

4. store 추상화 + 스키마 이식

  • 드라이버 인터페이스: record_envelope·fetch_rows·summary_counts·priority_*·fetch_resource_history·priority_lineage 등 공개 메서드를 백엔드별로 구현(DuckdbBackend/PostgresBackend). 기존 시그니처 유지.
  • SQL 방언 변환:
    • upsert: DuckDB INSERT OR IGNORE/keep-best → PG INSERT … ON CONFLICT(request_id) DO UPDATE(keep-best 조건 동일 적용).
    • prefix-join(입력큐 계보): r.request_id >= ps.request_id||'-' AND < ||'.' — PG에서도 그대로(인덱스 범위스캔).
    • parquet COPY: store에서 제거 → DuckDB-over-PG 경로로.
  • DDL + 인덱스(성능 핵심 — DuckDB는 인덱스 없이 풀스캔이라 무거웠다): 
    CREATE TABLE single_simulation_results (request_id text PRIMARY KEY, …, started_at timestamptz, terminal_state text, peetsfea_version text, node text, partition text, …);
CREATE INDEX ON single_simulation_results (started_at);
CREATE INDEX ON single_simulation_results (terminal_state);
CREATE INDEX ON single_simulation_results (peetsfea_version);
CREATE TABLE priority_sweeps (request_id text PRIMARY KEY, …, remaining_count int, created_at double precision);
CREATE TABLE resource_snapshots (ts double precision, …);  -- 또는 keeper 소형 DB 유지
    → summary/results/timeseries가 인덱스로 가벼워져 24GB 같은 메모리 불필요.

5. 데이터 이관 (11GB)

  • DuckDB로 Postgres ATTACH 후 INSERT INTO pg.single_simulation_results SELECT * FROM duck.… (또는 parquet 경유 COPY). 배치/청크.
  • 스냅샷 + 증분: 이관 시작 시점 스냅샷 → web는 계속 DuckDB로 받음 → 컷오버 직전 started_at > 스냅샷ts 증분만 재이관 → 유실 0에 근접.
  • 검증: 행수 일치, terminal_state 분포 일치, 샘플 request_id 정밀비교.

6. 컷오버 (컨테이너 무중단)

  1. Postgres 기동 + 스키마 + 스냅샷 이관(여기까지 web은 DuckDB로 정상 운영, 컨테이너 무영향).
  2. dev에서 PostgresBackend 검증 완료된 코드 배포.
  3. 컷오버: 증분 이관 → EDT_STORE_BACKEND=postgres로 web 재시작(몇 분 ingest 공백 = 그 사이 결과 몇 분치만 유실, 워커는 reference sweep 계속). 무손실 원하면 그 순간만 safe_scancel 후 재개.
  4. 검증(아래) 통과 후 DuckDB store 은퇴(export 전용 잔존). 문제 시 EDT_STORE_BACKEND=duckdb로 즉시 롤백.

7. 대시보드 보강 (이번에 함께)

7.1 컨테이너 부하 탭 "솔브중 0" 문제

  • 원인: 컨테이너 카드의 "솔브중"이 제어기 per_job().active(permit/heartbeat 집계)인데, 이게 실제 솔브를 과소계상(솔브 사이 idle·heartbeat 누락 → 0으로 보임). lmstat 실측(노드별 elec_solve)과 불일치.
  • 해결: 폴러가 lmstat에서 노드별 elec_solve_hfss(+electronics_desktop) 체크아웃 수를 host별로 집계(이미 lmstat은 host별 라인 보유) → 스냅샷 nodes[node].solve/nodes[node].desktop. 대시보드 컨테이너 카드의 "솔브중"을 그 노드의 elec_solve 실측으로 표기(제어기 per_job 대체/병기). 노드=잡=컨테이너라 정확.

7.2 라이선스 electronics_desktop 표기

  • 컨테이너 탭 헤더/개요에 electronics_desktop 사용을 명확히: 내것/전체사용 (총 발급) 예 "electronics_desktop 200/245 (총 550)". 추가로 elec_solve(솔브)도 병기(예 "solve 190/210") — 데스크톱 vs 솔브 구분이 보이게.
  • 이미 폴러가 두 feature를 다 카운트(이전 작업) → 스냅샷 license.mine/in_use/issued(desktop) + solve_mine/solve_in_use. 대시보드 표기만 보강.

8. 테스트

  • store 단위: 기존 테스트를 PostgresBackend로도 통과(파라미터화) — record/upsert/keep-best, fetch_rows, summary, priority_*, lineage(prefix-join), resource_history.
  • 대시보드: /api/summary·results·queue/lineage·resources가 PG 백엔드로 동작. 솔브중=노드별 elec_solve, 라이선스 표기.
  • 이관: 행수·분포·샘플 일치.
  • 부하: summary/results 동시 호출 + ingest write 동시 — 락·OOM·spill 0(MVCC). 텔레메트리 결측 0.

9. 롤아웃 / 롤백

  • dev에서 전부 개발·검증(유저공간 PG 띄워 통합테스트) → 통과 후 main FF + 서비스 재시작.
  • 롤백: EDT_STORE_BACKEND=duckdb 토글 + web 재시작이면 DuckDB store로 즉시 복귀(이관 중에도 DuckDB 원본 보존).
  • 컨테이너: 마이그레이션 전체 동안 가동 유지(컷오버 몇 분 공백만, 또는 그 순간만 정지).

10. 리스크

  • 유저공간 PG 운영부담(+1 서비스) ↔ 안정성·인덱스 이득. 백업: pg_dump 주기.
  • parquet export가 DuckDB-over-PG로 바뀜 → 경로/성능 검증 필요.
  • 이관 시간(11GB) — 스냅샷+증분으로 무중단 흡수.
  • SQL 방언 누락 위험 → 백엔드 추상화 + 테스트 파라미터화로 커버.

11. 작업 순서 (착수 시)

  1. 유저공간 PG 설치·기동(systemd --user) + psycopg.
  2. store 백엔드 추상화 + PostgresBackend + DDL/인덱스. 테스트 파라미터화 통과(dev).
  3. 대시보드 7.1/7.2 보강(노드별 elec_solve, 라이선스 표기) — DuckDB 백엔드로도 동작하니 먼저 머지 가능.
  4. 스냅샷 이관 + 검증.
  5. 컷오버(증분 + backend 토글 + web 재시작) → 검증 → DuckDB store 은퇴.
  6. main FF + 재시작.
