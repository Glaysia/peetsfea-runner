적분 컨테이너 제어 — 잡 고정 + 컨테이너 수 적분 피드백

지령 = 유효 AEDT 120 / 잡 10 / 리플 최소. PLANS/job_birth_controller.html(홀짝·LUT) 폐기 대체 · 누수=PID-ns 격리로 분리됨([[leak-reclaim-needs-pid-ns]]) · 2026-06-21 · 설계(미구현, 검토용)

한 줄 요지: 잡-죽임으로 제어하면 통째(±컨테이너 묶음)로 출렁여 리플. 잡을 안정 인프라로 고정하고, 제어는 컨테이너 수를 적분(I) 피드백으로 ±소량 미세 조정한다. 누수 회수는 더 이상 제어가 겸직하지 않는다(컨테이너 1솔브=죽음 + PID-ns 격리가 전담).

1. 왜 바꾸나 — 현행의 리플 원인

  • 현행 _managed_poll: 2분 tick에 홀수=잡 4개 submit / 짝수=가장 오래된 잡 kill, +12분 포화제어(solve>150시 oldest kill), +squeue-stuck 회복. 잡 1개 = 컨테이너 ~12개 = 유효 AEDT ~12 묶음.
  • 잡 단위로 ±하니 actuation 분해능이 ±12 AEDT. 코호트가 통째로 뜨고/지며 유효 AEDT가 출렁인다(실측 리플 stddev 26→44).
  • 게다가 잡-죽임이 누수 회수까지 겸직해서, 제어하려고 잡을 죽이면 멀쩡한 솔브도 같이 버려졌다.

2. 새 구조 — 두 관심사 분리

3. 제어 법칙 (적분 I)

매 tick (Δt = 30~60s):
  aedt   = 유효_AEDT_관측()                # elec_solve_hfss 동시 솔브 수 (solve_provider)
  err    = 120 - aedt
  step   = clamp(round(Ki * err), -ΔN_max, +ΔN_max)   # Ki≈0.3~0.5, ΔN_max=3
  N_total = clamp(N_total + step, N_min, N_max)        # 적분 상태 = 총 컨테이너 수
  per_job = 분배(N_total, 잡 10개)                      # 균등 + 나머지 라운드로빈
  → 각 잡 orchestrator가 /job_plan에서 per_job[i]를 읽어 respawn-to-N
  • 적분이라 정상상태 오차 0: 평균이 정확히 120으로 수렴(비례항만 쓰면 옵셋 남음).
  • step 클램프(±3)로 한 tick의 출렁임 제한 → 매끈한 출생률(Little's Law: λ≈120/11.5≈10.4 컨/min이면 솔브중=120 일정).
  • N은 컨테이너 단위라 분해능 ±1~3 AEDT(잡 단위 ±12 대비 4~12배 미세).
  • 콜드스타트 herd 차단: 잡당 출생은 orchestrator가 stagger+cold_cap으로 이미 처리(웨이브 금지).
