잡별 디버그 접근 — 잡마다 sshd + 전용 포트

돌고 있는 임의의 잡 노드/컨테이너에 바로 ssh로 디버깅을 빠르게. 클러스터 22 미사용 · 다계정 포트 베이스와 정합 · 구현·검증 완료 · 2026-06-21

한 줄 요지: 클러스터 노드 22번 sshd는 중앙인증(IPA/Kerberos 등)이라 우리가 키를 못 넣는다 — 자기 노드 자기 자신에게도 등록 키 거부 확인됨. 그래서 잡마다 우리 소유 sshd를 노드-로컬 포트에 non-root로 띄우고(우리 host key + authorized_keys, StrictModes no·UsePAM no → 평유저로 우리 키만 받음), 그 포트를 게이트의 결정적 포트로 역터널한다. 로컬에서 ssh -J <gate> -p <port> -i edt_debug <user>@127.0.0.1 한 방으로 잡 노드 진입 → enroot exec로 컨테이너 안까지. 검증: n114 진입·컨테이너/AEDT 관측 성공.

1. 동기 — 지금의 한계

  • 지금 잡 노드에 들어가는 길은 srun --jobid=N --overlap --pty bash뿐. SLURM 큐/권한에 묶이고, scp·IDE 리모트·GUI 포워딩 같은 ssh 도구를 못 쓴다.
  • 컨테이너 누수/AEDT 행(hang)/gRPC 문제를 볼 때 대화형 ssh + 포트 포워딩이 절실하다(debugpy attach, pyaedt 라이브 inspect, VS Code Remote).
  • orchestrator엔 이미 EDT_ORCH_SSHD_PORT(-R ${SSHD}:127.0.0.1:22) 백채널 훅이 있다 — 기본 off(0). 이걸 잡별로 켜고 전용 포트를 더하면 끝.

2. 포트 할당 스킴 (결정적 · 다계정 정합)

충돌 없이 잡 인덱스+계정만으로 포트가 정해져야 한다(같은 게이트 머신을 두 계정이 공유 → [[multi-account-ingest-port-collision]]과 동일 함정). 7900–7999를 디버그용으로 예약, 계정 stride 50.

용도공식harry261(acct0)hmlee31(acct1)
게이트 포트(역터널 바인드)
EDT_ORCH_SSHD_PORT		7900 + 50·acct + job7900–79087950–7958
노드-로컬 sshd 포트(우리 sshd listen)
EDT_DEBUG_LOCAL_SSHD		2200 + 50·acct + job2200–22082250–2258

잡 9개(0–8) 기준. 두 포트 다 (계정×잡)별로 유일 — 게이트는 1대(공유)라 게이트 포트가, 한 노드에 두 잡이 co-locate할 수 있어 노드-로컬 포트가 각각 충돌나면 안 된다. 제어/데이터 포트(7876–7889)와 별도 대역. launcher가 둘 다 결정적으로 계산·주입. env 베이스: EDT_DEBUG_SSHD_BASE(7900, 0=비활성)·EDT_ACCOUNT_INDEX·런처 debug_local_base(2200)·debug_account_stride(50).

3. 우리 소유 sshd + 역터널 (구현됨)

우리 sshd @ node:127.0.0.1:<local>— orchestrator -R → gate 127.0.0.1:<gate_port>— 로컬 ssh -J -i edt_debug → 잡 노드 셸
  • 왜 22가 아니라 우리 sshd인가: 노드 22 sshd는 중앙인증이라 ~/.ssh/authorized_keys를 무시한다(자기 노드 자기 자신에게도 등록 키 거부 실측). 우리 sshd면 인증 규칙이 전부 우리 것.
  • orchestrator setup_debug_sshd()(EDT_ORCH_SSHD_PORT>0일 때): 호스트키·클라이언트키 자동생성(idempotent) + authorized_keys 자동등록 + non-root sshd를 EDT_DEBUG_LOCAL_SSHD에 기동(StrictModes no·UsePAM no). keep_tunnel이 -R ${gate}:127.0.0.1:${local}로 역노출.
  • 노드는 host netns 공유라 노드 셸에서 enroot list·enroot exec <c> bash로 컨테이너 안, pgrep -a ansysedt로 AEDT까지 바로.
  • 잡 종료 시 trap이 sshd + 터널 ssh를 죽여 포트·프로세스 자동 회수(잔류 0).
  • 검증: hmlee31 job0 → 우리 sshd node:2250 ← gate:7950, 로컬 ssh -J … -p 7950 -i edt_debug로 n114 진입·컨테이너/AEDT 관측 성공.

4. 잡별 전용 디버그 포트

잡마다 임의 서비스 1개를 로컬로 당기는 범용 포트. 컴퓨트 노드 loopback의 한 포트를 게이트로 역터널하고, 노드에서 그 포트로 무엇을 띄울지는 디버깅 상황에 따라.

쓰임방법
pyaedt/AEDT gRPC 라이브 inspect컨테이너의 -grpcsrv <p>를 노드 디버그 포트로 socat 중계 → 로컬에서 pyaedt attach
python 원격 디버거컨테이너 entrypoint를 EDT_DEBUGPY=1로 띄우면 debugpy가 디버그 포트 listen → 로컬 VS Code attach
잡 상태 endpointorchestrator가 디버그 포트에 live/SPAWNED/ctnr/ansysedt 미니 HTTP 서빙(관측)

5. 접속 레시피 (로컬에서) — 검증됨

# 0) 클라이언트 개인키 한 번만 로컬로 (orchestrator가 게이트에 자동생성해둠)
scp <gate>:~/edt-deploy/debug/edt_debug ~/.ssh/edt_debug && chmod 600 ~/.ssh/edt_debug

# 1) 잡 i 노드 진입 (acct=hmlee31 → gate_port = 7950+i)
ssh -J gate1-hmlee31 -p 7950 -i ~/.ssh/edt_debug -o IdentitiesOnly=yes \
    -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
    hmlee31@127.0.0.1            # job 0 노드. i번 잡은 -p $((7950+i))

# 2) 노드 안에서: 컨테이너/AEDT 들여다보기
enroot list
enroot exec edt-<JOB>-<id>-<pid> bash      # 컨테이너 안 셸
pgrep -a ansysedt ; ls /proc/<pid>/fd | wc -l
대시보드/헬퍼가 잡별로 완성된 ssh 명령을 출력해주면(포트가 job_index+account로 결정적이라 자동 생성) 클릭 한 번 디버깅. /health·부하탭에 잡별 ssh_cmd 필드 추가(후속).

7. 정리 · 보안

  • 전부 게이트 loopback(127.0.0.1) 바인딩 — 외부 노출 없음(GatewayPorts off). 같은 게이트의 해당 계정만 도달.
  • 인증은 기존 ssh 키. 노드 sshd는 본인 잡 노드라 본인 키로 접속.
  • 잡 종료 시 orchestrator trap이 터널 ssh 종료 → 게이트 포트 즉시 회수. 잔류/누수 없음.
  • 디버그 전용·기본 off: EDT_DEBUG_SSHD_PORT 미설정(0)이면 비활성(프로덕션 기본). 필요 시 잡/계정 단위로 켠다.
  • ephemeral 호스트키라 StrictHostKeyChecking=no(같은 포트가 시간에 따라 다른 노드).

8. 단계

  1. orchestrator.sh에 디버그 -R 2줄 + env 게이트(값 0이면 skip).
  2. launcher가 잡별 결정적 포트 주입(account×job). hmlee31에서 ssh -J … -p 7950로 노드 진입 검증.
  3. 대시보드 잡별 ssh_cmd 출력.
  4. (선택) entrypoint debugpy + gRPC 중계 헬퍼.

— 포트 스킴은 다계정 제어/데이터 포트 베이스(7876 harry261 / 7886 hmlee31)와 같은 철학: 계정×역할로 결정적 분리, 게이트 loopback, 잡 종료 시 자동 회수.
