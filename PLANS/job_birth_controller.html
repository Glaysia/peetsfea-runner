제어 로직 — 4분 잡 제출 루프 · 동시 솔브 100 수렴

컨테이너 1솔브=죽음 · squeue 최대 15 · 정상상태 RUNNING 10 + PENDING 5 · 2026-06-19

1. 모델 한눈에

  • 컨테이너 = 1 솔브 = 죽음. 재가동(respawn) 없음 → 잡의 살아있는 컨테이너는 시간이 지나며 줄어든다(드레인).
  • 잡 = 출생 시 컨테이너 N개(≤20) 가동. 수명 최대 20분.
  • 제어 루프는 잡 수 구간을 보지 않는다. 4분마다 같은 행동을 반복한다.
  • squeue 상한은 15개이며, 정상상태 목표는 RUNNING 10개 + PENDING 5개다.
  • 목표: 동시 솔브 100에 수렴. 잡 제출은 노드별 균등 분산이 필요하다.

2. 제어 루프 (핵심) — 4분마다 고정 행동

매 4분→ 가장 늙은 RUNNING 잡 1개 종료+ 새 잡 4개 제출→ squeue 최대 15 
every 4 minutes:
    if squeue_count >= 15 and queue_is_stuck:
        stop_oldest_running_job()
        submit_jobs(1, spread="node-even")
        return

    stop_oldest_running_job()
    submit_jobs(4, spread="node-even", squeue_cap=15)

target steady state:
    RUNNING jobs = 10
    PENDING jobs = 5
    squeue total = 15
  • 잡 수 구간 없음: 램프/정상 단계를 나누지 않고 매 tick 같은 루틴을 실행한다.
  • 종료 후보: 현재 켜져 있는 RUNNING 잡 중 가장 오래된 잡 1개를 내린다.
  • 제출: 매 tick 새 잡 4개를 요청하되, 후보 노드를 한쪽으로 몰지 않고 노드별로 균등 분산한다.
  • stuck 회복: squeue가 15개로 꽉 찼는데 진행이 막히면 가장 늙은 잡 1개를 내리고 추가 잡 1개만 요청한다.
  • 잡 수명 20분 = 하드 상한(그 전에 틱 교체/드레인되면 더 일찍 종료). 종료 시 AEDT·pyaedt·터널 소멸 → 누수 회수.
  • 새 잡마다 컨테이너 수 N은 출생 시 LUT(§3)로 결정.

3. N 결정 — LUT (잡 출생 시)

새 잡의 컨테이너 수 N은 현재 elec_solve_hfss 실측을 보고 계단형 LUT로 정한다. 낮을수록 세게 밀고, 150 근처에서는 잡당 10개까지 낮춘다.

solve = 현재 동시 솔브 수            # 실측 elec_solve_hfss (우리)

if   solve <=  90: N = 20
elif solve <= 100: N = 15
elif solve <= 110: N = 14
elif solve <= 120: N = 13
elif solve <= 130: N = 12
elif solve <= 140: N = 11
else             : N = 10
solve0~90100110120130140150+
N20151413121110
  • 0~90: 잡당 20개로 최대 밀기.
  • 100~150: 10 solve 증가마다 N을 1씩 낮춰 과한 출생을 줄인다.
  • 150 이상: 잡당 10개를 유지하고, 별도 포화 제어가 늙은 잡을 추가로 정리한다.

4. 포화 제어 — 12분마다 추가 감압

4분 제어 루프 세 번에 한 번(= 12분마다) 라이선스 사용량을 확인한다. elec_solve_hfss > 150이면 현재 켜져 있는 RUNNING 잡 중 가장 늙은 잡 1개를 추가로 종료한다. 
every third 4-minute tick:
    if license_solve_in_use > 150:
        stop_oldest_running_job()

5. herd 방지 (컨테이너 출생 stagger)

잡이 N개를 한꺼번에 켜면 그 노드에서 AEDT N개 동시 기동 → 방금 본 gRPC 행 재발. → orchestrator는 N개를 1개씩 간격 두고 가동(노드당 동시 콜드스타트 ≤ EDT_COLD_CAP=10).

6. 구현 포인트

레이어변경
제어기(루프)잡 수 구간을 보지 않고 4분마다 가장 늙은 잡 1개 종료 + 새 잡 4개 제출. squeue 총량은 15개로 제한하고, stuck 시 1개 종료 + 1개 요청.
orchestrator출생 시 N 받아 1솔브 컨테이너 N개 stagger 가동(respawn 없음). EDT_JOB_TTL_SEC=1200 또는 제어기 종료신호 시 진행 솔브 마치고 안전종료 → 잡 exit. /enroot 정리 trap 유지.
keeper노드별 균등 분산으로 제출하고, 정상상태 RUNNING 10 + PENDING 5를 유지한다. 12분마다 solve >150 포화 감압을 수행한다.
