제어 로직 — 10분 롤링 교체 · 20분 잡 · 동시 솔브 100 수렴

컨테이너 1솔브=죽음 · 잡당 최대 20 · 로드밸런싱 없음 · 2026-06-19

1. 모델 한눈에

  • 컨테이너 = 1 솔브 = 죽음. 재가동(respawn) 없음 → 잡의 살아있는 컨테이너는 시간이 지나며 줄어든다(드레인).
  • 잡 = 출생 시 컨테이너 N개(≤20) 가동. 수명 최대 20분.
  • 제어 루프 2단계: 잡 1~7개는 1분마다 +1 순증(탈락 없는 빠른 램프), 8~9개는 10분마다 1탈락+채움(9 유지).
  • 목표: 동시 솔브 100에 수렴. 로드밸런싱 없음(SLURM 배치에 맡김).

2. 제어 루프 (핵심) — 잡 수에 따라 2단계

잡 1~7개→ 1분마다 새 잡 1개 제출(탈락 없음) — 순증 잡 8~9개→ 10분마다 최소-컨테이너 잡 1탈락+ (10−잡수)개 제출 → 9 유지 
jobs = 현재 RUNNING 잡 수

if jobs <= 7:                # ── 램프 단계 ── 빠르게 9로 채움
    매 1분: submit_job(N=decide_N())     # 탈락 없음, 순증

elif jobs in (8, 9):         # ── 정상 단계 ── 9 유지하며 롤링 교체
    매 10분:
        J = 살아있는 컨테이너가 가장 적은 RUNNING 잡   # 가장 많이 끝난 잡(손실 최소)
        safe_stop(J)                                  # 1개 탈락
        for _ in range(10 - jobs):                    # 9개→1제출, 8개→2제출
            submit_job(N=decide_N())                  # → 9로 복귀
  • 램프(1~7): 탈락 없이 1분당 1잡 순증 → ~7분이면 9 근처 도달(빠름).
  • 정상(8~9): 10분마다 가장 적게 남은 잡(거의 끝난 잡) 안전종료 → in-flight 손실 최소 + 출생/사망 stagger로 herd 제거.
  • 잡 수명 20분 = 하드 상한(그 전에 틱 교체/드레인되면 더 일찍 종료). 종료 시 AEDT·pyaedt·터널 소멸 → 누수 회수.
  • 새 잡마다 컨테이너 수 N은 출생 시 LUT(§3)로 결정.

3. N 결정 — LUT (잡 출생 시)

지령(setpoint) solve=100에서 이상점 N=12(잡당 12개 = 9×12≈108). 100~120 오버슈팅은 좋음(밴드), 120↑은 정지. 최대 20.

solve = 현재 동시 솔브 수            # 실측 elec_solve_hfss (우리)

if   solve <= 100:  N = 12 + 0.08*(100 - solve)   # 100→12, 0→20  (밑일수록 더 밀기)
elif solve <= 120:  N = 12 - 0.55*(solve - 100)   # 100→12, 120→1 (오버슈팅 100~120 허용)
else            :  N = 1                           # 120↑ 오버슈팅 정지
N = clamp(round(N), 1, 20)

  • 100 미만: 12보다 크게(최대 20) 밀어 올림 — 멀수록 세게.
  • 100~120: 12에서 1로 완만히 줄이며 오버슈팅 허용(이 구간 체류 OK).
  • 120 초과: 최소 1 — 더 안 밀어 120 근처서 멈춤.

4. herd 방지 (컨테이너 출생 stagger)

잡이 N개를 한꺼번에 켜면 그 노드에서 AEDT N개 동시 기동 → 방금 본 gRPC 행 재발. → orchestrator는 N개를 1개씩 간격 두고 가동(노드당 동시 콜드스타트 ≤ EDT_COLD_CAP=10).

5. 구현 포인트

레이어변경
