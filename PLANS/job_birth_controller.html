제어 로직 — 15분 롤링 교체 · 30분 잡 · 동시 솔브 100 수렴

컨테이너 1솔브=죽음 · 잡당 최대 20 · 로드밸런싱 없음 · 2026-06-19

1. 모델 한눈에

  • 컨테이너 = 1 솔브 = 죽음. 재가동(respawn) 없음 → 잡의 살아있는 컨테이너는 시간이 지나며 줄어든다(드레인).
  • 잡 = 출생 시 컨테이너 N개(≤20) 가동. 수명 최대 30분.
  • 제어 루프 = 최대 15분 주기로 롤링 교체. 항상 ~9잡 유지.
  • 목표: 동시 솔브 100에 수렴. 로드밸런싱 없음(SLURM 배치에 맡김).

2. 제어 루프 (핵심)

15분(또는 더 빨리)마다→ 살아있는 컨테이너 가장 적게 남은 잡 선택→ 그 잡 안전종료→ 제어기 N 결정→ 새 30분 잡(N) 제출 
제어 틱 주기 = 최대 15분.
  단 어떤 잡의 컨테이너가 다 끝나(드레인) 자리가 비면 15분 전이라도 즉시 틱.

매 틱:
  J = 살아있는 컨테이너가 가장 적은 RUNNING 잡   # 가장 많이 끝난 잡(손실 최소)
  safe_stop(J)                                   # 남은 소수 컨테이너만 안전종료
  N = decide_N()                                 # 아래 공식
  submit_job(ttl=30min, containers=N)
  • 가장 적게 남은 잡을 끔 → 거의 끝난 잡이라 중단해도 in-flight 손실 최소.
  • 잡 수명 30분 = 하드 상한(그 전에 틱으로 교체되거나 드레인되면 더 일찍 종료). 종료 시 AEDT·pyaedt·터널 소멸 → 누수 회수.
  • 틱마다 1개 종료 + 1개 출생 → 출생/사망이 시간축에 분산(stagger) → gRPC 동시 herd 제거.

3. N 결정 — LUT (잡 출생 시)

지령(setpoint) solve=100에서 이상점 N=12(잡당 12개 = 9×12≈108). 100~120 오버슈팅은 좋음(밴드), 120↑은 정지. 최대 20.

solve = 현재 동시 솔브 수            # 실측 elec_solve_hfss (우리)

if   solve <= 100:  N = 12 + 0.08*(100 - solve)   # 100→12, 0→20  (밑일수록 더 밀기)
elif solve <= 120:  N = 12 - 0.55*(solve - 100)   # 100→12, 120→1 (오버슈팅 100~120 허용)
else            :  N = 1                           # 120↑ 오버슈팅 정지
N = clamp(round(N), 1, 20)

  • 100 미만: 12보다 크게(최대 20) 밀어 올림 — 멀수록 세게.
  • 100~120: 12에서 1로 완만히 줄이며 오버슈팅 허용(이 구간 체류 OK).
  • 120 초과: 최소 1 — 더 안 밀어 120 근처서 멈춤.

4. herd 방지 (컨테이너 출생 stagger)

잡이 N개를 한꺼번에 켜면 그 노드에서 AEDT N개 동시 기동 → 방금 본 gRPC 행 재발. → orchestrator는 N개를 1개씩 간격 두고 가동(노드당 콜드스타트중 ≤2~3).
